## 1. لوحة التحكم (Admin Panel) — أولوية قصوى

- [ ] **رمز الدخول مشفر أو يُفحص من جهة سيرفر** — حاليًا `almaali2026` موجود كنص صريح في كود الجافاسكريبت (`AdminDashboard.tsx:84`). أي زائر يفتح `View Page Source` يشوفه. الحل الأبسط: استخدم Supabase Auth (مستخدم واحد، كلمة مرور)، أو على الأقل سو hash للكلمة داخل الكود.
- [ ] **لوحة التحكم لها مسار مشفر** — بدل ما تكون `#admin` اللي أي شخص يعرف يفتحها، استخدم رمز إضافي في الرابط أو key سري.
- [ ] **جلسة الإدارة تنتهي تلقائيًا** — بعد 30 دقيقة من عدم النشاط، طرد تلقائي.

## 2. قاعدة البيانات (Supabase) — ضروري

- [ ] **Row Level Security (RLS) مفعّل فعليًا** — الكود الموجود في `supabase.ts:70-72` يسمح لأي شخص لديه `anon key` بالكتابة والحذف. صلّح السياسات: PUBLIC users → `SELECT` فقط، ADMIN فقط له `ALL` عبر `supabase.auth`.
- [ ] **`.env` ما ينرفع لـ GitHub** — تأكد إن `.gitignore` يمنع رفع ملف `.env`. حاليًا الملف موجود بمفاتيح حقيقية.
- [ ] **`anon key` له صلاحيات قراءة فقط** — سياسات RLS لازم تمنع `INSERT/UPDATE/DELETE` للمستخدمين المجهولين.
- [ ] **الـ `created_at` موجود على كل جدول** — ✅ تم (موجود في الـ schema).

## 3. API الخارجية — مفتاح Gemini

- [ ] **مفتاح Gemini API** — ما يستخدم نهائيًا في الكود الحالي (فقط مكتبة منزلة). إذا استخدمته لاحقًا، تأكد إن المفتاح:
  - محدود الصلاحيات (scoped) على قدر الحاجة
  - ما ينكشف في كود الـ frontend أبدًا

## 4. رفع الصور — أمان أساسي

- [ ] **منع رفع ملفات ضارة** — حاليًا الأبلكيشن يحوّل الصور لـ `base64 data URL` ويخزنها مباشرة. هذا عدم أمان:
  - لو الصورة تنرفع لـ Supabase Storage، استخدم `supabase.storage` مع قيود على نوع الملف وحجمه.
  - لو قاعدة البيانات بتستقبل Base64، أي ملف ضار ينحفظ كنص ويُعرض لاحقًا — خطر XSS. نظّف المخرجات أو استخدم CDN/Storage منفصل.
- [ ] **التحقق من حجم الصورة** — حاليًا مذكور "Max 5MB" في الـ UI لكن لا يوجد تحقق فعلي في الكود.

## 5. زوار الموقع — لا يوجد قلق كبير

- [ ] **WhatsApp link** ما يرسل أي بيانات حساسة — ✅ الموقع فقط يفتح `wa.me` بدون إرسال معلومات عن الزائر.
- [ ] **الموقع ما يخزن بصمة زائر (tracking)** — ✅ لا Google Analytics، لا cookies، لا sessions، لا LocalStorage للمستخدمين.
- [ ] **كل المحتوى العام (خدمات، أطباء، صور، مقالات)** — ✅ متاح للجميع بدون تسجيل، وهذا مناسب لموقع تعريفي.

## 6. تحسينات مستقبلية (أولوية منخفضة)

- [ ] **حماية الـ Email من السكرابينج** — البريد الإلكتروني في الـ Footer موجود كنص عادي.
- [ ] **CSP Header (Content Security Policy)** — يمنع تنفيذ سكربتات غير متوقعة في المتصفح.
- [ ] **Rate limiting على Supabase** — لو تعرض الموقع لهجوم، Supabase يوفر حماية مدمجة. تأكد من مراقبة الاستخدام.
- [ ] **تحديث دوري للمكتبات** — `npm audit` بشكل دوري.
